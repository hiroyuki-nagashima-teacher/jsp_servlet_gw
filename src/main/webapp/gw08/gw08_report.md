## 3. JSPに書く/書かない判断表（作業3）

| 処理内容 | JSPに書いてよいか | 理由 | 分けるならどこに置くか |
| --- | --- | --- | --- |
| 値を画面に表示する | **よい** | JSPはプレゼンテーション層（画面表示）を担当するため、コントローラーから受け取ったデータを表示するのは本来の役割だから。 | 画面表示のままでよい（出力時にエスケープ処理を行う） |
| 数値や日付の表示形式を整える | **よい** | 表示のフォーマット変更は画面表示の範疇であり、JSTLの `fmt` タグを用いて画面側で制御するのが適しているから。 | 画面表示のままでよい（`fmt:formatNumber` や `fmt:formatDate` を使用） |
| 画面表示用に短い文字列処理を行う | **よい** | 表示のために必要な軽微な文字列処理（文字数取得や簡易置換等）は、画面側でFunctionsタグ等を使って柔軟に行うのが自然だから。 | 画面表示のままでよい（`fn` タグを使用） |
| 入力値をもとにSELECT文を実行する | **よくない** | JSPの中にSQLが直接記述されると、画面デザイン変更とDB処理変更の影響が混ざり、保守性やテスト容易性が大きく低下するため。 | DAO (Data Access Object) または Service クラス |
| INSERTやUPDATEを実行する | **よくない** | データ登録や更新には入力値チェック、例外処理、トランザクション制御（コミットやロールバック）が必要であり、これらをJSPで安全に行うことは極めて難しいため。 | Service クラスや DAO クラス |
| 複雑な業務ルールを判定する | **よくない** | ビジネスロジックをJSPに書くと再利用できず、ロジック変更時に画面も修正が必要になり、単体テストもできなくなるため。 | Service クラス（ビジネスロジック層） |
| DB接続情報を管理する | **よくない** | DB接続のURLやパスワードなどの設定情報をJSP内に直書きすると、セキュリティ漏洩リスクが高まり、環境ごとの切り替えも困難になるため。 | 設定ファイル（`context.xml` 等）で管理し、ServletやDAOからデータソース経由で取得する |
| 同じ処理を複数画面で再利用する | **よくない** | 各JSPに同じコードを複製（コピー＆ペースト）すると、仕様変更の際に全てのファイルを修正せねばならず、バグや修正漏れの原因となるため。 | 共通のServlet、Filter、共通ユーティリティクラス、またはカスタムタグ |

## 4. タグ・関数の役割整理表（作業4）

| タグ・関数 | 役割 | 使いどころ |
| --- | --- | --- |
| fmt：formatNumber | 数値をカンマ区切りの数値、通貨記号、パーセントなどの指定した形式に整形して表示する。 | 金額を `￥1,234` のように表したり、小数値を `10%` のようにパーセンテージで表示したいとき。 |
| fmt：formatDate | 日付や日時のオブジェクトを指定したパターン（書式）にフォーマットして表示する。 | 現在の日時やデータベースから取得した日付を `2026年06月05日 10時30分` のように分かりやすく表示したいとき。 |
| fmt：setLocale | 特定の国や地域（ロケール）を指定し、それ以降のフォーマット動作（通貨記号や日付書式）に影響を与える。 | 多言語対応のWebページを作成するときや、金額表示の通貨記号を日本の円（`ja_JP`）などに固定したいとき。 |
| fmt：requestEncoding | リクエスト（特にPOST）から取得するデータの文字エンコーディングを指定する。 | JSPでPOST送信された値を受け取る際、Servletを経由せずに直接JSPでパラメータを読み込む時の日本語文字化け対策。 |
| fn：length | 文字列の文字数、またはコレクションや配列の要素数を取得する。 | EL式の中で文字列の長さを判定したり、リストの要素数に基づいて表示内容を制御したいとき。 |
| fn：contains | 対象の文字列に、指定した特定の文字列が含まれているか判定する（真偽値を返す）。 | `c:if` タグなどを使って、検索ワードや特定の文字が含まれる場合だけ一部の表示を切り替えたいとき。 |
| fn：replace | 文字列の中の指定された箇所を、別の文字列に置換する。 | 画面上の特定の文言や文字（例：改行文字や特定の記号）を別の表記に変換して表示したいとき。 |
| fn：split | 文字列を指定した区切り文字で分割し、文字列の配列を生成する。 | カンマ区切りの文字列（CSV）を分割して配列化し、`c:forEach` でループ出力したいとき。 |
| fn：join | 文字列配列の各要素を指定した文字で連結し、1つの文字列にする。 | 分割されたリストデータを、画面上で ` / ` や `,` で繋いで1行で綺麗に見せたいとき。 |
| sql：setDataSource | JSPでデータベースにアクセスするためのデータソース接続情報を定義・準備する。 | プロトタイプ作成や簡易的な動作チェック用に、JSPからDBに繋ぐための設定を行いたいとき。 |
| sql：query | データベースに対して `SELECT` 文を実行し、結果セットを取得する。 | JSP内だけで手軽にDBからデータを読み込み、テーブル形式などで一覧表示させたいとき。 |
| sql：update | データベースに対して `INSERT`、`UPDATE`、`DELETE` などの更新SQLを実行する。 | JSP内だけで手軽にデータベースのレコード追加・更新・削除などの操作を行いたいとき。 |
| sql：param | SQL文内のプレースホルダー（`?`）に対して安全にパラメータを割り当てる。 | `sql:query` や `sql:update` の実行時に、SQLインジェクション対策としてパラメータを安全にバインドしたいとき。 |

## 5. 発表メモ（作業5）

私たちのグループでは、Formattingタグは
**[ 数値、通貨、パーセント、日付などの表示形式をユーザー向けに整えたり、多言語対応（ロケール）の制御を行う ]**
のために使うタグだと整理しました。

fmt：requestEncodingは
**[ POST送信されたリクエストパラメータの文字エンコーディングを設定し、受け取る日本語データの文字化けを防ぐ ]**
のために使うタグだと整理しました。

Functionsタグは
**[ EL式の中で文字列の長さ取得、検索、置換、分割、結合などの簡易的な文字列処理を行う ]**
のために使うものだと整理しました。

Databaseタグは
**[ JSPから直接データベースへの接続、SQL（SELECT/INSERT/UPDATE/DELETE）の実行、およびパラメータのバインド ]**
を行うためのタグだと整理しました。

ただし、DatabaseタグをJSPで使う場合、
**[ 画面表示とDB処理が混在してコードの保守性や再利用性が著しく低下し、機密情報の露出やトランザクション制御の困難さといったセキュリティ・品質上の問題が発生する ]**
という注意点があると考えました。

JSPに書いてよい処理は
**[ コントローラーから受け取ったデータの画面表示や、表示用データの簡易的なフォーマット・文字列処理 ]**
のような処理で、JSP以外に分けたい処理は
**[ データベースアクセス（SQL実行）、トランザクション制御、業務ルールの判定（ビジネスロジック）、DB接続情報の管理 ]**
のような処理だと考えました。
